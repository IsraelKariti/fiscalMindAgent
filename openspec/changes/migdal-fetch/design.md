## Goals / Non-Goals

**Goals:**
- A `migdal` provider that mirrors the Harel/Phoenix shape so nothing generic changes.
- Four deterministic filter rounds (2 report types × 2 products) that fail loudly when a filter never ran or the year is not offered, and never download health reports or another year.

**Non-Goals:**
- Using the site's JSON API directly (`customerPeriodReports` / `imagedocument`): the UI path is what was verified; the auth header shape was not captured.
- The email code channel, passport login ("זיהוי עם דרכון"), the "תשלחו לי במייל" footer, other report types (הצהרת הון, רבעוני, אישור מס) — out of scope; the "הצהרת הון" report type is noted for a possible later change.
- Treating the short report as its own checklist item (owner's decision: it rides on the same row as the full report).

## Decisions

1. **Entry URL = the login page itself** (`/mymigdal/process/login`; it is what the public site's "מגדל שלי" button opens and it is static — no one-time state). The provider waits for `input#username` rather than a URL.
2. **Login = id only.** `startLogin` requires credential `idNumber` and ignores any phone. It types the id with `typeHuman`, asserts `#otpToCell` is checked (clicks its label if not), clicks the form's submit button, then waits for `input[name=otp]` to be visible (45 s). Worker `buildCredentials` returns `{ idNumber }` and still requires `client.wa_phone` (the code is relayed over WhatsApp), returning null without it.
3. **OTP entry = keyboard into the first box.** Click `input[name=otp]`, then `page.keyboard.type` the six digits with a human delay; the site's auto-advance moves focus box to box. After typing, read the six boxes; if any is empty (auto-advance absent), fill each box `input[name=otp<n>]` individually. Then click the submit button. Success = URL contains `/mymigdal/lobby/` within 45 s. Timeout with `input[name=otp]` still visible = `OtpRejectedError` (all six boxes cleared for the retry); anything else = login failed. The wrong-code path is confirmed in the live check and tightened if the site shows a distinct error element.
4. **Navigation = direct `page.goto('/mymigdal/info/approvals')`** after login; wait for `select#selectApprovalType` (60 s).
5. **Rounds** = fixed list `[{type:'דוח שנתי', product:'פנסיה', kind:'pension_annual'}, {type:'דוח שנתי', product:'השתלמות', kind:'study_fund_annual'}, {type:'דוח שנתי מקוצר', product:'פנסיה', kind:'pension_annual'}, {type:'דוח שנתי מקוצר', product:'השתלמות', kind:'study_fund_annual'}]`. Per round: `selectOption({label: type})` on the type select; wait until the product select's options change / contain more than the placeholder (10 s); if no option with the product label exists → log "product not offered" and continue to the next round (this is how "the client holds no study fund" shows). Else select it. Year: if `select#selectYear` is absent, press "הצג אישור" once (with the product selected) to make it render, wait for it; `selectOption({label: String(taxYear)})` — a missing year option throws (generic failure → download-failed outcome; the spec forbids downloading another year). Press "הצג אישור" (armed `waitForResponse` on `customerPeriodReports` first, like Harel's `watchFilterRoundTrip`), then wait until either the "נמצאו" heading or the "לא מצאנו נתונים לתצוגה" text is visible (30 s); neither = throw ("filter never answered").
6. **Row reading** = `a[aria-label="להורדת המסמך"]` with non-empty text, title = text with whitespace collapsed. Kind comes from the round, never from the title (study-fund titles unobserved). A title not containing `String(taxYear)` is skipped with a log line (defensive against a year filter that did not apply). Dedup per kind by title across rounds (the full and the short report have different titles, so both survive). A pure, unit-tested `selectMigdalRows(rows, taxYear, kind)` holds the year check + dedup.
7. **Download = Playwright `download` event** around a click on the title link (Phoenix's `captureDownload`, 60 s per file, human-cadence pauses between files). `filename` = `download.suggestedFilename()` or a slug of the title; `title` = the row title; `kind` per decision 5; `contentType` application/pdf.
8. **Outcome**: no file in any round and at least one round answered (empty text or product not offered) → `NoDocumentsOnSiteError`; a round that never answered → generic error. No explicit logout: the server closes the browser, as for every provider.
9. **Worker spec** (`migdalSpec`): id `migdal`, `siteNameHe` "מגדל", `otpChannel: 'sms'`, `takesAllDocuments: true`; documents `pension_annual` (`/מגדל|מקפת|migdal/i` ∧ `/פנסיה|גמל|מקפת/` ∧ ¬`/השתלמות/`, `catalogTypeKey: 'pension_provident'`) and `study_fund_annual` (`/מגדל|מקפת|migdal/i` ∧ `/השתלמות/`, `catalogTypeKey: 'study_fund'`). Delivery wording copies Phoenix's product-noun joiner and per-file titles; `fileLabel` = `"<title> — מגדל <year>"`. Canned messages mirror Phoenix's SMS texts with "מגדל", and `otpSent` adds that the SMS went to the mobile number registered at Migdal (the client may not expect it on the WhatsApp number).
10. **Mock**: `MockTaxFetchClient.downloadDocuments` gets a `migdal` branch returning two files per agreed key: pension "דוח שנתי לעמית- מקפת אישית - לשנת <year>" + "דוח שנתי מקוצר לעמית -מקפת אישית - לשנת <year>", study fund "דוח שנתי לעמית - קרן השתלמות - לשנת <year>" + "דוח שנתי מקוצר לעמית - קרן השתלמות - לשנת <year>" (study-fund titles are invented for the mock only).
11. **No new access-catalog entry, no migration, no runner protocol bump**: the catalog already lists `migdal` for both products; provider ids are free text in the DB; the runner HTTP contract is unchanged. `PortalProvider` gains `'migdal'`.
12. **Smoke script** `scripts/migdalFetchSmoke.ts <idNumber> [taxYear]` (no phone argument), same shape as the Phoenix one, writing PDFs to `<tmp>/migdal-smoke/`.

## Risks / Trade-offs

- [The year dropdown may only render after a search] → decision 5 does a priming search when it is absent; if the live check shows it renders on product selection, the priming step is a no-op.
- [The year filter may not apply server-side (the owner saw `Year: ""` for "all years" only)] → the title must carry the year (decision 6), so a non-applied filter can only skip rows, never deliver another year.
- [Auto-advance between the six code boxes is assumed] → decision 3 verifies the boxes after typing and falls back to per-box fills.
- [Product option labels per account] → a missing product label ends the round quietly; a missing type label (the type list is global) throws.
- [Wrong-code behaviour unverified] → inferred detection as for Phoenix; tightened after the live check.
- [Glassbox/AppDynamics bot heuristics] → human-cadence pauses and the runner's headful Chrome, as for Harel/Phoenix; the owner's live clicks produced real downloads.
- [Study-fund row titles unobserved] → selection never depends on them; the live check on an account with a study fund (if the owner has one available) confirms the round.

## Migration Plan

No DB migration. Deploy = normal push (worker + browser-runner image are built per commit). Rollback = revert the commit; a `migdal` session mid-flight on a rolled-back worker fails with "unknown provider", which the existing failure path handles.
