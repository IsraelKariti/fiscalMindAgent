## Context

See proposal.md — Why. The fetch machinery is provider-structured: a runner-side `DocumentFetchProvider` (`src/browserRunner/`, drives one Playwright page: `startLogin` → `submitOtp` → `downloadDocuments`) and a worker-side `FetchProviderSpec` (`taxFetch/providers.ts`: document types, credentials, canned texts, delivery wording). Sessions, OTP relay, delivery, bring-everything consent (`effectiveFetchKeys`), row creation at delivery (`planFetchedRows`, keyed on `takesAllDocuments` + `catalogTypeKey` + `siteNameHe`), the prompt block and the site-access screen are generic and need no change. Migdal (`src/browserRunner/migdal.ts`, archived change `migdal-fetch`) is the closest template.

## Goals / Non-Goals

**Goals:**
- A `meitav` provider that mirrors the Migdal shape so nothing generic changes.
- The login and code steps ported from the reference, with the wrong-code detection the reference captured (a real error element — better than Migdal's inferred timeout).
- The download step driven by the periodic-reports page exactly as crawled: year picker, one pass over the product cards, both annual reports per card, popup download.

**Non-Goals:**
- The Meitav Trade area (securities portfolio report at 31.12): a separate provider or document type later, if wanted; this provider never takes Trade documents.
- The email code channel ("לקבלת סיסמא במייל ללקוחות בחו"ל"), the employer and agent logins, the mobile app.
- Pressing "send again" automatically (the site locks after "unusual attempts").
- Using the Meitav JSON API directly (`GetPeriodicReports` / `DownloadReport` by `Statementid`): the UI path is what was verified end to end; the API shape is recorded only so a future change can fall back to it.
- The "דוחות ואישורים" generator page (`/Amitim/ReportingPages/ReportingView`) and "הפקת אישורים": not crawled; the periodic-reports page already holds the annual reports.

## Decisions

1. **Entry URL = the member login page** `https://customers.meitav.co.il/v2/login/loginAmit` (static, what the reference used). The provider waits for `#id-identity-input` (90 s), like the other providers wait for their id field.

2. **Phone split in a pure helper.** `splitMeitavPhone(phone)` → `{ prefix, digits }`: strips a leading `972` to `0`, strips spaces/dashes, requires a prefix from the site's list `['050','051','052','053','054','055','057','058']` and exactly seven remaining digits; throws otherwise. `startLogin` calls it before `page.goto`, so a number the site cannot take fails the session with the login-failed outcome before the site is touched (the worker maps any `startLogin` error to `loginFailed`). Alternative — letting the site reject it — costs a browser launch and gives a vaguer failure. Unit-tested in `tests/meitavPhone.test.ts`.

3. **Login = reference steps, with the repo's helpers.** `typeHuman` the id → Tab; `selectOption(prefix)` on `select[name=prefixPhone]` then `evaluate(el => el.dispatchEvent(new Event('change', {bubbles: true})))` (the reference found AngularJS needs it); `typeHuman` the seven digits → Tab; wait for `button#submit:not([disabled])` (15 s; if it never enables, throw "form did not validate" — the reference only warned and clicked anyway, which hides a typing problem); `humanPause`; click. Then wait for `#codeDigitsInput` visible (45 s) = the SMS was sent. Credentials: `idNumber` and `phoneNumber` via `requireCredential`.

4. **OTP = single field.** `clearOtp` (Ctrl+A, Delete), `typeHuman` the six digits into `#codeDigitsInput`, Tab, wait for `button.login-id-btn:not([disabled])` (10 s — a code that is not six digits never enables it: throw `OtpRejectedError` so the client is re-asked, as Migdal does for a wrong digit count), short `humanPause` (1–3 s; the code expires in minutes), click. Then race three outcomes (45 s): URL no longer contains `/login` → success; `label.errorLabel[ng-show="GeneralError"]` visible → clear the field, throw `OtpRejectedError('Meitav rejected the one-time code')`; neither → throw "login did not complete". Alternative — Migdal's inferred rejection (code screen still up after the wait) — is kept as the fallback branch when the timeout fires and `#codeDigitsInput` is still visible, so a changed error element still yields a retryable rejection. The success check is "left `/login`", not a lobby path, because the landing is account-dependent (`/home/MyAccount.aspx` for the gemel lobby, `/tradelobby` for a Trade-only account) and the next step navigates directly to the reports page anyway.

5. **Worker spec** (`meitavSpec`): id `meitav`, `siteNameHe` "מיטב", `otpChannel: 'sms'`, `takesAllDocuments: true`; documents `pension_annual` (`MEITAV_NAME = /מיטב|meitav/i` ∧ `/פנסיה|גמל/` ∧ ¬`/השתלמות/` ∧ ¬`TRADE = /טרייד|trade|ניירות ערך/i`, `catalogTypeKey: 'pension_provident'`) and `study_fund_annual` (`MEITAV_NAME` ∧ `/השתלמות/` ∧ ¬`TRADE`, `catalogTypeKey: 'study_fund'`). The Trade exclusion keeps a "— מיטב טרייד" securities row from making this provider offerable (spec scenario). `buildCredentials` = `clientIdNumber(client, 'meitav')` + `client.wa_phone` → `{ idNumber, phoneNumber }` (null without either). Delivery wording copies Migdal's product-noun joiner and per-file titles; `fileLabel` = `"<title> — מיטב <year>"`. Canned messages mirror Migdal's SMS texts with "מיטב". `PortalProvider` gains `'meitav'`.

6. **Download = one page, one year, every product card.** `downloadDocuments` navigates to `/home/myaccount/periodicreports`, waits for `#selectYear` (60 s) and for the list request to have answered (the first `div.reportsList` or the year picker's options), then opens the year picker through its "Open" button and reads `#selectYear-listbox [role=option]` texts. If the tax year is not among them → `NoDocumentsOnSiteError` (the picker lists only the years with reports, so a missing year is "nothing for that year", not a site change; the picker is closed with Escape first). Otherwise the option with the year's text is clicked and the picker's value is asserted to equal the year. Then every card is read: the card header (the nearest ancestor of a `div.reportsList` whose text starts with the product name, i.e. the text before "מספר חשבון") gives the kind — `/השתלמות/` → `study_fund_annual`, `/פנסיה|גמל/` → `pension_annual`, anything else → skipped with a log line; its `div.reportsList li` rows give the titles. A pure `selectMeitavRows(rows, taxYear, kind, seen)` keeps rows whose title matches `/דוח שנתי/`, carries the year as a four-digit string and is not `/רבעוני/`, deduped by collapsed title within a kind — unit-tested. Each selected `li` is clicked through `captureNextPdf` (`pdfCapture.ts`: it already races a popup, a download event on the page or the popup, and an application/pdf response — exactly Meitav's `window.open` → attachment mechanism), with human-cadence pauses between rows; `title` = the row title, `filename` = the suggested filename or a slug of the title, `kind` from the card. No annual row anywhere for the year (only quarterly rows, or no card of a known product) → `NoDocumentsOnSiteError`. The rounds of Migdal are not needed: the page shows every product at once.

7. **Session liveness.** The crawl saw the download answer 401 once the session had expired (the member session timed out while we explored). The runner's whole flow runs inside the existing session TTL and downloads right after the year is set, so no extra keep-alive is built; a 401 surfaces as "PDF not captured" → download-failed, with the failure screenshot.

8. **Mock**: `MockTaxFetchClient.downloadDocuments` gets a `meitav` branch returning the two real titles per agreed key: "דוח שנתי מפורט דצמבר <year>" and "דוח שנתי מקוצר דצמבר <year>" (the titles are the same for every product on the site, so the mock uses them for the study fund too).

9. **No new access-catalog entry, no migration, no runner protocol bump**: the catalog already lists `meitav` for both products; provider ids are free text in the DB; the runner HTTP contract is unchanged.

10. **Smoke script** `scripts/meitavFetchSmoke.ts <idNumber> <phone> [taxYear]`, same shape as the Migdal one, writing PDFs to `<tmp>/meitav-smoke/`. The owner's own account holds a pension with reports for 2023, so the whole chain (login, code, year 2023, two PDFs) is checkable live.

## Risks / Trade-offs

- [The study-fund card was not observed] → kind is read from the card header with `/השתלמות/`, the pension/gemel from `/פנסיה|גמל/`; an unknown header is logged and skipped, never mis-tagged. The first study-fund client confirms the header text.
- [The landing after login is account-dependent] → success is "left `/login`", and the reports page is navigated to directly.
- [MUI Autocomplete year picker] → opened through its "Open" button and chosen by option text; the picker's value is asserted after the click so a missed option fails loudly instead of fetching the default (latest) year.
- [Invisible reCAPTCHA on the login page] → the reference's runs passed with human typing and the same webdriver masking the repo's `launchInteractivePage` already applies (`--disable-blink-features=AutomationControlled`); a challenge would surface as "form did not validate" / "code screen never appeared" = login-failed, and the failure screenshot shows it.
- [AngularJS needs real input events] → char-by-char `typeHuman` and the dispatched `change` event on the prefix select (both from the reference); the submit button's enabled state is the proof the form validated.
- [Resend lockout "ניסיונות חריגים"] → the platform never presses resend; a client who waits too long simply starts a new session.
- [Session expiry before the download] → downloads follow the year selection immediately; a 401 shows as download-failed with the screenshot (decision 7).

## Migration Plan

No DB migration. Deploy = normal push (worker + browser-runner image are built per commit). Rollback = revert the commit; a `meitav` session mid-flight on a rolled-back worker fails with "unknown provider", which the existing failure path handles.
